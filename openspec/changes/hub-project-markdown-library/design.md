## Context

当前项目页只有概览、Wiki、代码、维护和项目设置。Wiki Reader 的页面来自 `wiki.json`，工具条、历史和写回流程绑定 OpenZread/Zread Provider；搜索也只遍历这两类 Catalog。普通 Markdown 可以复用文章渲染、目录宽度调整和大纲定位能力，但其身份、链接、保存与问答范围不同。另一个进行中的 `hub-project-library-multi-wiki` change 将建设项目/Wiki 侧栏树；本 change 在其项目节点下增加 Markdown 分支，不改写那份 change 的 Wiki 实例定义。

## Goals / Non-Goals

**Goals:**

- 让项目内非 Provider 管理的 Markdown 原文件可发现、按目录浏览、阅读、搜索、Ask AI 和编辑写回。
- 从全局侧栏或搜索结果点击文件后，主区域直接打开准确文档，保持 Wiki 与 Markdown 两种工作区的状态隔离。
- 在大项目、外部文件变化和链接路径越界时给出明确结果，不误读、误写其他文件。

**Non-Goals:**

- Markdown 不成为第三个 AI Wiki Provider；不生成 `wiki.json`，不参与 Wiki 生成、同步、版本指针或页面结构操作。
- 不自动把任意 Markdown 合并成章节型 Wiki，不自动重写链接或移动文件；不实现跨整仓的 AI 检索增强问答。
- 不把 Markdown 文件复制到应用数据库作为内容主本；不自动将 AI 回答应用到文件。

## Decisions

### 1. 独立内容类型与轻量文件索引

`local_markdown` 是内容来源类型，不扩展 `HubWikiProvider` 枚举。文件身份为 `projectId + normalized project-relative path`，文档改名/移动等于旧身份失效；项目重新定位但内部相对路径不变时身份保持。原文件是唯一权威内容；目录树/搜索索引只存相对路径、标题、大小、修改时间及必要的检索缓存，不产生 Wiki Catalog。候选扩展名为 `.md`、`.markdown`（大小写不敏感）。树保留真实文件夹层级，只显示含候选文件的文件夹；树标题优先一级标题或 YAML front matter 的 `title`，无标题则显示文件名，并始终可查看真实相对路径。

发现复用多 Wiki 扫描的注册项目根目录和边界策略，但不依赖 Wiki `wikiId`：跳过 `.git`、`node_modules`、`.open-zread`、`.zread` 与已知生成输出目录，不跟随 symlink/junction/reparse point；读取、图片、保存、搜索命中打开与问答前均重新解析文件，确认实际路径仍在注册项目内且未进入排除目录。Markdown 树头提供显式“刷新”，重新扫描项目并更新树及本地/全局搜索索引；刷新完成后按稳定文件路径保留仍存在的展开节点与当前文件，消失或移走的目标显示失效提示，绝不按同名文件替代。达到目录/文件/大小预算时返回“部分结果”及原因，支持重试；单个损坏或非 UTF-8 文件不得阻断其他文件。用户不需要在磁盘上创建“Markdown Wiki”目录。相比建立第三种 Provider，这避免了无意义的生成和版本语义；相比纯文件树，索引让全文搜索与最近阅读成为可能。

### 2. 独立 Markdown 页签，但沿用成熟的阅读交互

项目导航增加“Markdown”页签。全局侧栏的 `项目库 → 项目 → Markdown → 文件夹 → 文件` 是快捷入口；点击文件直接切换到该项目的 Markdown 页签并选中文件。页签内左侧保留可调宽、可收起的目录树与本目录搜索，中间以可用宽度显示文章，右侧提供可收起的大纲与 Ask AI 面板；大纲标题高亮、悬浮与点击定位沿用 Wiki Reader 的可用交互。项目级导航条紧接工作区，不再插入重复项目卡/大块空白。全局树与页内树使用同一文件身份与选中状态，避免两个不一致的目录来源。

Markdown 工具条只显示文档路径、刷新、编辑、在文件夹中显示及 Ask AI；不显示 Wiki Provider 切换、New page、Wiki History、生成/同步。页签入口无已选文件时显示选择/空状态；最近文档仅在仍存在时恢复，否则提示重新选择。每个项目保存最近文件和滚动位置，Wiki 会话键不变。切页、切文件和离开项目前，对未保存草稿使用现有离开保护。窗体变窄时左右栏可收起，文章仍可滚动和阅读。

把 Markdown block/inline 渲染和大纲逻辑从 Wiki 容器中抽成共享阅读层，但不把任意文件包装成 `HubWikiDocument`。渲染至少覆盖 GFM 常用结构、代码高亮、表格、Mermaid、相对图片和链接；原始 HTML 不得执行脚本。相对 `.md` 链接（含标题锚点）在同项目内导航，其他本地源文件沿用安全预览，外部 URL 明确交给系统浏览器；越界、缺失或被排除的资源显示可理解的错误，不静默打开。路径解析以当前文档所在目录为基准，不以项目根目录或 Wiki 版本目录代替。

### 3. 原文件编辑是独立的受控写入

编辑读取原文和修订哈希，预览显示同一相对路径的 diff 与渲染结果；用户确认后后端重新解析目标、检查其仍为候选 Markdown 且修订未变，再以同目录临时文件原子替换原文件。维持原始 UTF-8 BOM 和换行风格；保存前在应用数据区创建可恢复快照，保存成功后更新树、索引、文章及搜索结果。若外部编辑、文件消失、路径越界、权限不足或保存失败，拒绝覆盖并保留草稿，提供重载/复制草稿/比较的恢复入口；不自动合并，也不回退到同名文件。恢复快照不等于 Provider 的 Wiki History。这样满足“直接写回原文件”，又避免使用 Wiki ChangeSet 的 Catalog/版本假设。

### 4. 搜索与 Ask AI 共享文档身份，不共享写入语义

Markdown 页签可在当前项目按文件名、相对路径和正文搜索；Hub 全局搜索增加 `sourceKind=local_markdown` 的结果，与 Wiki 结果并列但清楚标注来源。结果包含项目 ID、相对文件路径、标题、片段及命中位置；点击前重新校验文件并打开 Markdown 页签，定位命中正文。删除、改名和索引过期的命中给出刷新提示，不跳到其他文件。大项目检索异步运行，扫描限制、部分结果和单文件读取错误分别报告，不让 Markdown 错误阻断 Wiki 结果。

Ask AI 默认仅发送当前文档、用户问题和可选选中文字给已配置模型；界面在发送前说明范围和外发事实。服务端重新读取目标原文件并施加输入大小限制，不信任客户端提供的绝对路径或正文；模型不可用、文件变化和超限分别报错。回答可显示当前文件路径/标题作为来源，不凭空标为跨文档结论；问答本身只读。若用户采纳 AI 修改，须显式进入普通编辑预览与确认流程。右栏可在大纲/Ask AI 间切换，但目录树和当前文档不因此丢失。

## Risks / Trade-offs

- [巨大或含生成目录的项目导致扫描慢] → 异步、排除目录、预算和部分结果提示；用文件元数据增量刷新，实际读取时再次校验。
- [相对链接、图片或 reparse point 越界] → 后端 canonicalize、项目包含检查、拒绝排除目录与非候选文档编辑；不直接信任前端路径。
- [共享旧 Wiki Reader 导致错误工具条或写错 Provider 文件] → 共享纯展示组件，Markdown 使用独立文件服务与编辑命令，契约用判别字段区分来源。
- [外部编辑覆盖] → 修订哈希、确认前重验、原子替换、可恢复快照和草稿保留。
- [AI 泄露过多项目内容或把文档指令当命令] → 默认单文件上下文、显式外发提示、大小限制、文档内容视为数据，回答不自动写回。
- [与多 Wiki 侧栏 change 同时开发冲突] → 先落地/对齐其项目树和结果身份，再增加 Markdown 分支；两个 change 不复用 `wikiId` 表示普通文件。

## Migration Plan

1. 在现有项目数据上增加 Markdown 发现与独立契约；不迁移或改写任何用户 Markdown 文件。先完成或集成 `hub-project-library-multi-wiki` 的项目树基础，避免实现两套侧栏树。
2. 接入 Markdown 页签、共享渲染、目录树与只读导航，再接入带冲突保护的原文件编辑、搜索和 Ask AI。
3. 旧项目/Wiki 偏好保持原样；Markdown 最近文件与滚动状态作为新字段增量保存。禁用新入口可回到原 Wiki 行为；索引可删除后重建，不影响原文件。
4. 使用含根目录与嵌套文档、重复文件名、相对资源、外部修改、越界链接、大目录和部分损坏文件的夹具验证；实施后执行测试、OpenSpec 校验并重建 Windows MSI。
