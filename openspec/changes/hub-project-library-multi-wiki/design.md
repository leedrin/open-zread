## Context

Hub 目前以项目注册路径作为唯一 Wiki 根：`projects.rs` 只检查该路径下的 `.open-zread/wiki`、`.zread/wiki`，Reader、搜索、资源、维护和任务命令也以 `projectId + provider` 定位。前端阅读偏好同样按这两个字段隔离。项目注册表只有名称、路径、收藏和最近打开时间，没有添加时间；项目卡菜单位于卡片内部，卡片悬浮变换会建立新的层叠上下文。

本设计落实 [proposal.md](proposal.md) 的五项需求，并沿用 [hub-ux-redesign](../hub-ux-redesign/design.md) 的项目工作区、ChangeSet 写回和阅读布局。Windows/Tauri 的本地目录是数据来源；Wiki 原文件仍留在各自子目录。

## Goals / Non-Goals

**Goals:**

- 项目库菜单在相邻卡片、滚动容器和窗口边缘仍完整可用；名称可编辑且排序结果可预测。
- 一次项目注册可发现根目录及子目录中的多份 Wiki，并让阅读、搜索、源码/图片、维护与生成始终作用于所选实例。
- 左侧项目/Wiki 树和项目内 Wiki 切换使用同一实例清单；旧项目、根目录 Wiki 和阅读偏好保持可用。

**Non-Goals:**

- 不把每个子目录注册为新的顶层项目，不移动或重写现有 Wiki 文件，不自动生成缺失的 Wiki。
- 不在不同 Wiki 间按标题/slug 合并页面、迁移历史或共享草稿；不引入在线搜索或第三种 Provider。
- 重命名只改变 Hub 的显示名，不改磁盘目录、Git 仓库名或 Wiki 标题。

## Decisions

### 1. 独立的 Wiki 实例身份与发现服务

一个 Wiki 实例由 `projectId + provider + project-relative sourceRoot` 唯一识别；根目录用 `.` 表示。后端返回稳定的 `wikiId`、相对目录、可读状态和显示标签，前端只传 `wikiId` 调用实例相关操作。`wikiId` 由规范化后的 Provider/相对目录确定，在项目重新定位但内部结构不变时保持不变；目录更名或移走后视为旧实例消失，不静默跳到同 Provider 的另一份 Wiki。

新增独立的实例发现/列举命令。项目导入后触发扫描，侧栏展开、进入项目和显式“重新扫描 Wiki”时可刷新；对大项目异步返回加载状态。扫描从注册项目根目录遍历真实子目录，检查每个候选源目录下的 `.open-zread/wiki` 与 `.zread/wiki`，复用现有 Catalog/版本指针检查得到 `readable/partial/invalid`；只有目录标记存在才列出实例。遍历不跟随符号链接、junction/reparse point，不进入 `.git`、`node_modules`、`.open-zread`、`.zread` 等内部/依赖目录；使用可观测的目录数量上限，达到上限时返回“扫描不完整”及已发现结果，并允许选择具体子目录补充定位。扫描失败不使已注册项目消失。

所有实例路径在后端重新由注册路径解析并 canonicalize，确认源目录及 Wiki 目录仍位于注册项目内；前端传来的 `wikiId` 不能直接拼接成文件路径。发现状态只描述本地文件现状，不把上一次扫描结果当作读写授权。根目录旧接口可临时默认到根实例，任何带有嵌套 `wikiId` 的调用都必须严格校验其目标，不允许失败后回退到根目录。选择该方案是为了避免把每份 Wiki 当成重复项目，也避免仅在 React 中存绝对路径。

### 2. 实例范围贯穿服务边界

在 `hub-contract` 与 application service 中补充实例清单及 `wikiId`。Reader、章节搜索与跨项目搜索结果、源码/图片读取、AI 问答、ChangeSet 预览/应用、创建/删除/元数据、历史和生成/同步任务均携带目标实例。搜索结果包含 `projectId + wikiId + slug`；失败按实例报告。源码引用以该实例的源目录为基准，图片以该实例当前 Wiki/版本目录为基准；两者仍执行既有目录包含检查。

写入预览记录目标实例身份和源文件修订；应用前再次验证实例路径、Catalog/版本指针及原文件修订。生成/同步任务的工作目录为实例源目录，队列、事件和续跑 checkpoint 记录 `wikiId`，失败后只能继续同一实例。根目录历史数据保持原位置；嵌套实例的历史与 checkpoint 留在对应源目录。若选中实例消失，UI 显示该实例不可用并提供重新扫描/返回选择，不改写其他 Wiki。设计把实例解析放在共用后端入口，避免各命令以略有差异的方式拼接路径。

### 3. 项目库菜单、重命名和排序

项目卡更多菜单使用顶层浮层（portal）锚定触发器，随滚动/窗口变化重新定位，靠近边缘时翻转或平移到可视区域。一次只开一个菜单；外部点击、Escape、选中动作会关闭，关闭后焦点回到触发器。浮层不依赖卡片自身的 z-index，因此不受卡片 hover `transform` 影响。

点击名称进入内联编辑；Enter/明确保存提交，Escape 取消，空白或非法控制字符被阻止，失败保留输入并显示错误。后端以 `projectId` 更新注册表名称并返回更新后的项目，不触碰磁盘目录；允许不同项目同名，界面以路径辅助辨认。

新注册记录保存 `addedAt`。旧记录没有可信添加时间，保留为空并在 UI 标为“添加时间未知”；按添加时间排序时它们排在有时间记录之后，同类沿注册表原顺序稳定排列，不以最近打开时间或文件修改时间伪造日期。项目库提供“收藏优先”（现有默认）、名称升/降序、添加时间新/旧优先；显式选择名称/日期时收藏只作为筛选条件，不覆盖主排序。排序选择存在本地偏好中，项目卡、筛选与返回项目库共用该选择；首页最近项目仍依据最近访问记录。

### 4. 侧栏树、实例切换与偏好迁移

“项目库”仍可直接进入项目库，同时有独立展开按钮。其下为项目节点；项目节点展开后显示该项目发现的每个 Wiki 实例，标签包括相对目录和 Provider，根目录标为“根目录”，相同名称仍能靠路径区分。点击项目进入项目概览；点击 Wiki 进入该实例的 Reader。项目内 Wiki 切换使用同一清单，保留当前项目导航布局，切换目标后恢复目标实例的独立阅读状态。侧栏收起时树隐藏但当前导航保留；展开项目时懒加载，空、加载、错误、部分扫描状态均有反馈。树支持方向键、Enter/Space、Escape 和清楚的选中/焦点状态。

导航状态、最近阅读、搜索跳转和 `readerSessions` 从 `projectId + provider` 升级为 `projectId + wikiId`；旧 Provider 会话只映射到根目录对应实例。旧偏好解析失败时局部丢弃损坏项，不清空整个项目库。树展开状态和项目库排序存本地偏好，项目移除/实例消失后忽略悬空引用。选择统一的实例键是为了阻止两个 OpenZread Wiki 的同名页面或滚动位置互相覆盖。

## Risks / Trade-offs

- [大仓库扫描耗时或漏扫] → 异步、跳过依赖目录、不跟随链接、限制目录数量；显示扫描不完整并提供指定子目录定位与重试。
- [子目录链接越过注册项目边界] → 每次读取/写入前 canonicalize 并检查包含关系；文件夹或版本指针变化后使旧操作失效。
- [实例参数遗漏导致操作误写根 Wiki] → 嵌套实例接口强制传 `wikiId`，预览和应用双重绑定实例，覆盖两个同 Provider Wiki 的回归用例。
- [旧项目没有真实添加时间] → 保留“未知”及稳定顺序，不推测日期。
- [菜单浮层与滚动/焦点冲突] → 浮层跟随锚点、边界翻转，键盘和窗口缩放验证。
- [进行中的 UX 改造仍未归档] → 实施时以当前工作区代码为准，并在归档前协调两份变更对项目库/Reader 的规范，避免覆盖已有导航和写回要求。

## Migration Plan

1. 扩展项目记录与实例清单契约；旧注册记录可直接读取，新增记录写入 `addedAt`，不迁移磁盘 Wiki。
2. 先打通实例发现和安全解析，再逐项接入 Reader、搜索、资源、维护及任务；根目录旧行为持续作为兼容路径。
3. 迁移阅读偏好中的旧 Provider 会话到根实例，启用项目库排序/重命名、侧栏树和项目内切换。
4. 用根目录与多个嵌套目录的混合项目验证权限边界、写回目标、搜索定位、续跑和 UI 状态；完成后按项目流程重建并核验 Windows MSI。

## Open Questions

无阻塞问题。实施时需测量真实大型项目的扫描耗时，再确定目录数量上限；规范要求达到上限时明确报告不完整并允许指定子目录定位。
