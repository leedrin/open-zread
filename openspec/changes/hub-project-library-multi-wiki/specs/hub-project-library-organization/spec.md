## ADDED Requirements

### Requirement: 项目卡更多菜单始终可见且可操作

Hub SHALL 让项目卡的更多菜单显示在相邻卡片和项目库滚动内容之上，并在窗口边缘调整位置，使全部菜单项可点击。Hub SHALL 同时只打开一个项目菜单，并支持键盘关闭及焦点返回。

#### Scenario: 相邻卡片遮挡
- **WHEN** 用户打开非最后一行项目卡的更多菜单，菜单延伸至其他卡片位置
- **THEN** 菜单完整显示在相邻卡片之上，菜单项可点击，不被卡片裁剪或覆盖

#### Scenario: 窗口边缘和滚动
- **WHEN** 用户在窄窗口或项目库滚动位置打开菜单
- **THEN** 菜单留在可视区域，并在滚动或缩放后保持对齐触发按钮

#### Scenario: 关闭菜单
- **WHEN** 用户按 Escape、点击菜单外或选择菜单项
- **THEN** 菜单关闭；通过键盘关闭时焦点返回原触发按钮

### Requirement: 在项目库重命名项目显示名

Hub SHALL 允许点击项目卡名称进入重命名状态，并按稳定项目 ID 更新 Hub 注册表中的显示名。Hub MUST NOT 因重命名修改本地项目目录、Git 仓库或 Wiki 文件。

#### Scenario: 提交新名称
- **WHEN** 用户点击名称、输入有效的新名称并按 Enter 或确认保存
- **THEN** 项目卡、侧栏树、项目面包屑和搜索结果使用新名称；项目路径与 ID 保持不变

#### Scenario: 取消与无效输入
- **WHEN** 用户按 Escape 或提交空白/包含控制字符的名称
- **THEN** Escape 恢复原名称；无效输入被拒绝并显示原因，注册表保持原名称

#### Scenario: 同名项目
- **WHEN** 两个不同路径的项目被命名为相同显示名
- **THEN** 两个项目保留各自 ID 与路径，界面提供路径以供区分

### Requirement: 项目库按名称或添加日期排序

Hub SHALL 提供名称升序、名称降序、添加日期新到旧、添加日期旧到新，以及保留现有收藏优先行为的默认排序。所选排序 SHALL 与搜索/收藏筛选组合使用，并在返回项目库及重启应用后保留。

#### Scenario: 按名称排序
- **WHEN** 用户选择名称排序并重命名一个项目
- **THEN** 项目立即按更新后的显示名重新排列，同名项以稳定次序显示

#### Scenario: 按添加日期排序
- **WHEN** 用户选择添加日期排序
- **THEN** 新项目依据首次加入 Hub 的时间排列，重新打开项目不会改变其添加日期

#### Scenario: 旧项目没有添加日期
- **WHEN** 旧版项目注册记录没有可验证的添加时间
- **THEN** Hub 将其日期标为“未知”，在按日期排序时列于已知日期项目之后，并保持旧项目间的稳定顺序

#### Scenario: 排序与筛选同时生效
- **WHEN** 用户启用仅看收藏并选择名称或日期排序
- **THEN** Hub 只显示收藏项目，且按用户选择的字段排序，不再强行把收藏状态作为主排序键
