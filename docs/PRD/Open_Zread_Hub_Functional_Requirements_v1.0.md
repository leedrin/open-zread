# Open Zread Hub 首版功能需求文档

版本：v1.0（审查稿）  
日期：2026-09-14  
依据：PRD v0.1、v0.2、v0.3，以及逐项交互确认的产品决策。  
状态：产品范围已确认；本文补充的验收细则与技术约束待审查。本文不是已实现功能清单，也不是最终技术设计。

## 1. 产品目标与交付边界

Open Zread Hub 是面向本地开发者的多项目、双 Wiki Provider 知识工作台。用户在一个 Windows 桌面应用中管理项目，阅读 OpenZread 与 Zread 的 Wiki，生成和更新文档，并持续编辑维护知识内容。

首版必须完成“接入项目 → 阅读已有 Wiki → 生成或更新 → 编辑 → 审阅应用 → 后续更新保留修改 → 历史恢复”的完整闭环。下面的开发里程碑用于分阶段验收，不代表将已确认的首版功能后置。

### 1.1 已确认的产品决策

| 编号 | 决策 |
|---|---|
| D01 | Windows 优先，采用 Tauri + React。 |
| D02 | 首版同时包含 OpenZread、Zread 的阅读、生成和统一编辑维护。 |
| D03 | 两个 Provider 的维护结果都直接写回各自原始 Wiki 文件，外部工具可见；首版不采用 Overlay。 |
| D04 | 更新或重新生成后自动保留无冲突修改，逐页审阅冲突；保留生成基线和恢复快照。 |
| D05 | 编辑包含手写/AI 新增、Markdown 编辑预览、小节/整页重写、目录维护、可恢复删除和关联源码维护。 |
| D06 | 自动检测源码变化，用户手动触发更新；不自动调用模型。 |
| D07 | OpenZread 生成与 Hub AI 编辑共用模型配置，Zread 生成使用自己的登录及配置。 |
| D08 | 首版包含跨项目全文搜索；范围是项目名、页面标题和已保存正文。 |
| D09 | 手动添加项目，支持非 Git 项目、已有双 Wiki、路径重新定位；移除不删除源码或 Wiki。 |
| D10 | 小节重写只能修改选中标题及其下属内容；整页重写为独立操作。 |
| D11 | 冲突页面保留更新前内容，其他页面可维护；再次更新该 Wiki 前须解决已有冲突。 |
| D12 | 每次应用记录历史，支持页面恢复、多页面操作撤销；恢复形成新记录。 |
| D13 | 全局默认一个生成或 AI 维护任务，其余排队；支持取消、退出提示及中断后手动重试。 |
| D14 | 安装 Hub 后无需 Node.js/Bun 即可使用内置 OpenZread；Zread CLI 单独安装。 |
| D15 | 保留单项目、单 Wiki 问答；会话隔离，回答落入正文须转为编辑草稿。 |
| D16 | 每份 Wiki 独立记忆页面和滚动位置，不自动跨 Provider 对齐页面。 |

### 1.2 首版不包含

批量 Workspace 扫描、CLI 自动注册、持续后台 File Watch、语义搜索、跨项目问答、多 Provider 综合回答、页面对齐与并排比较、Composite Wiki、Overlay/Managed Variant、风格分析系统、知识图谱、插件市场、MCP/Agent API、云同步、团队协作、完整 IDE、macOS/Linux 发布。

保留既有 CLI 的使用方式。Hub 首版不要求把所有 CLI 交互界面改造成桌面界面，也不承诺旧 CLI 直接写入时自动遵守 Hub 的全部维护规则。

## 2. 三版 PRD 的整合与修订

| 来源 | 保留内容 | 本稿处理 |

| v0.3 | 统一维护、ChangeSet、差异审阅、校验、修改保护 | 作为首版核心，基本冲突处理和历史恢复一并交付。 |
| v0.3 Overlay 建议 | 外部 Provider 原文不变 | 被 D03 替代：Zread 也直接写回原文，不实现 Overlay。 |

| v0.3 修改保护后置 | 保留修改策略和 Rebase 部分属于 P1/P2 | 按 D04/D11 提升：没有保护闭环不能交付可更新的编辑功能。 |

“不集中复制 Wiki”指不建立第二份长期编辑主库；用于比较和恢复的基线、快照、草稿属于必要辅助数据，不与原始 Wiki 争夺事实来源。

## 3. 术语与数据归属

| 术语 | 定义与规则 |
|---|---|
| 项目 Project | 一个用户注册的本地代码目录；有稳定 ID，路径可重新定位。非 Git 目录也可注册。 |
| Wiki Provider | 生产 Wiki 的工具。本文特指 OpenZread、Zread，不等同于模型服务商。 |
| Wiki Variant（简称 Wiki） | 项目下可独立阅读和维护的一份 Wiki。首版每项目分别接入一份 OpenZread 和一份 Zread Wiki。 |
| 页面 Page | 一篇 Markdown 文档，有稳定页面 ID；标题、slug、路径不是身份本身。 |
| 分类 Section / 分组 Group | 页面在目录中的组织位置，不等于正文中的标题小节。 |
| 正文小节 | 从选中标题开始，到下一同级或更高级标题之前的内容，包含下级标题。 |
| 生成基线 Baseline | 某次成功生成或更新后的、尚未重新合入维护修改的内容及目录状态。 |
| 当前版本 Current | 磁盘上正在使用的 Wiki，包含已应用维护；统一 Reader 与外部工具读取它。 |
| ChangeSet（变更集） | 针对指定 Wiki 修订生成的一组待应用或已应用的正文、目录、元数据变更。 |
| 快照 Snapshot | 操作前用于恢复的一致版本；与生成基线用途不同。 |
| 冲突 Conflict | 无法确定同时保留维护意图与新生成结果的页面或元数据变化。 |
| SourceReference | 页面的关联源码或出处；既有 associatedFiles 可映射为文件/目录引用。 |

身份规则：同一路径规范化后重复添加不产生重复项目；同一 Git Remote 的两个本地克隆仍是两个项目。重新定位由用户明确指定，不根据 Remote 自动合并。页面改名/移动保留 ID，外部页面无稳定 ID 时建立映射；匹配不确定时转人工处理。

数据归属：源码归项目；当前 Wiki 归 Provider 原生目录；Hub 保存项目注册、偏好、任务、维护历史、生成基线、恢复快照和搜索索引。搜索索引可重建，维护历史不是可任意丢弃的缓存。

Hub 元数据不得放入可能被 Provider 重生成清理的目录。具体目录及数据库格式留给技术设计；须明确备份、重新定位、移除后保留和手动清理的行为。既有 OpenZread 配置实际使用用户目录下 `.zread/config.yaml`，不能仅因产品命名而隐式迁移或覆盖配置。

## 4. 信息架构与主要流程

主导航：项目库、最近访问、收藏、搜索、任务、设置。项目内提供概览与统一 Wiki 工作区；工作区包含 Provider 切换、目录、正文、编辑/问答面板以及历史入口。无需为每项底层能力新建顶级导航。

默认进入上次使用的项目/Wiki；目标不可用时返回项目库并显示原因。每份 Wiki 分别保存阅读位置、目录展开状态和会话。

### 4.1 接入与阅读

选择项目目录 → 识别已有 Wiki 与生成器可用性 → 加入项目库 → 选择 Wiki → 阅读。没有 Wiki 时显示生成入口；没有模型或 Zread CLI 时仍允许读取已有内容。

### 4.2 编辑与应用

选择页面/小节 → 手动编辑或提交 AI 指令 → 保存草稿 → 查看差异及校验结果 → 应用 → 写回原文件、记录历史、刷新目录和搜索。

### 4.3 更新与修改保留

检测到源码变化 → 用户启动更新 → 保存当前快照 → 获取新的生成结果 → 基于旧生成基线比较维护修改 → 自动合入无冲突页面 → 有冲突页面继续展示更新前内容 → 用户逐页解决 → 完成更新。

## 5. 功能需求与验收标准

下列 FR 均为首版范围。“应/必须”表示交付要求；标为建议值的数值和实现方案仍需审查。

### FR-01 桌面安装与启动

- 提供 Windows 安装包；内置第一方运行能力及其必要静态资源/WASM。
- 阅读、搜索、手动编辑已有 Wiki 不需要开发运行时或模型配置；生成和 AI 操作需要有效模型配置。
- 程序不依赖启动时工作目录；内置运行器以明确路径启动，不从 PATH 随机选取同名旧版本。
- 保留独立 CLI，桌面升级不擅自改写其 PATH 或全局 npm 安装。

验收：在未安装 Node.js/Bun 的 Windows 测试机上安装，打开含中文和空格路径的项目，完成阅读、搜索、手动编辑；配置模型后可发起生成。设置页可确认内置运行器版本与位置。

### FR-02 项目注册与重新定位

- 手动选择本地目录；支持无 Wiki、无 Git 的项目，支持已有两种 Wiki。
- 显示名称、路径、Wiki 摘要、最近访问、收藏以及需要处理的事项；提供名称/路径筛选。
- 规范化真实路径去重；目录不可达、权限不足、格式损坏分别报告，不混成“未生成”。
- 路径失效保留项目记录；重新定位后校验目标并恢复原 ID、偏好和历史。目标已有注册时提示处理重复。
- 提供打开文件夹、打开终端、复制路径。
- 移除项目仅移除注册，源码、Wiki 和可恢复历史不随之删除；历史清理为独立明确操作。

验收：重复添加同一目录不重复；同 Remote 的不同克隆可共存；移动目录后重新定位保留收藏与历史；移除后源码和 Wiki 内容哈希不变。

### FR-03 双 Provider 检测与配置

- 区分“已有 Wiki 可读取”和“生成器可执行”；二者独立。
- OpenZread 使用内置运行能力；Zread CLI 自动检测并允许手动指定路径，显示实际版本、路径和健康状态。
- Zread 缺失时禁用生成，不禁用已有 Wiki 阅读和 Hub 编辑。
- Provider 的 Generate、Regenerate、Sync 等按钮按真实能力显示；不把不支持的增量更新伪装成 Sync。
- 设置页区分 Hub/OpenZread 模型配置与 Zread 自身配置。操作前展示使用的模型或 Zread 自有配置标识；无法读取时明确显示未知。
- 无需在 Hub 重新实现 Zread 登录；提供必要配置指引。登录失败或授权过期可恢复后重试。

验收：PATH 中有多个程序时能指定并核对实际目标；未安装 Zread 时仍能编辑其 Wiki；一个 Provider 故障不影响另一个。

### FR-04 统一模型与兼容读取

- 同一项目下两份 Wiki 共存，分别拥有状态、页面映射、历史和阅读位置。
- 统一读取目录、正文、图表、图片、内部链接与关联源码；保留 Provider 特有字段，写回不得无意丢失。
- OpenZread 适配原生分类路径；Zread 解析当前版本指针及实际页面路径，不假定 `current` 是目录。
- 支持已有内容的接入，不强制重新生成或移动 Wiki。首次接入保存当前快照，说明此前生成/维护历史未知。
- Zread 写入目标为当前指针解析后的真实版本；应用前再次检查指针和内容修订，防止写入失效版本。

验收：使用同项目双格式样例通过同一 Reader 读取；两份 Wiki 不覆盖、不混淆；导入再写回无关字段保持；版本指针改变使旧草稿进入重新核对而非写错目录。

### FR-05 阅读与导航

- 复用现有 Reader 的 Markdown、代码块、Mermaid、目录与源码查看体验。
- 独立保存每项目/每 Wiki 的页面及滚动位置；切换恢复各自位置，不按同名标题自动对齐。
- 原页面被删除时回到该 Wiki 概览并解释原因；文件缺失时显示局部错误，其他页面仍可阅读。
- 页面更新后刷新相关内容；编辑中的未保存草稿不得被后台刷新替换。
- 阅读不执行文档内脚本；外部链接由系统浏览器处理，本地链接受项目/已注册资源范围约束。

验收：A/B Wiki 来回切换恢复位置；含 Mermaid、图片、相对链接的样例正确显示；恶意 HTML 不执行；单个坏页面不阻塞项目。

### FR-06 生成与状态检测

- 打开项目时自动检查已有 Wiki 和源码变化；提供手动刷新，不自动调用模型。
- 区分内容可用性、源码新鲜度和当前任务，避免用一个 `error` 状态遮蔽仍可读的旧 Wiki。
- 无可靠检测依据显示“未知/可能过期”，不宣称最新。Git HEAD 不变也可能有未提交源码变化。
- 用户明确选择 Provider 发起生成/更新；展示目标项目、Wiki、操作范围、模型及可能覆盖提示。
- OpenZread 提供增量同步；Zread 按实测支持能力提供更新或重新生成。
- 生成退出成功后还须验证目录和页面输出；缺页或部分失败不能报告整份 Wiki 成功。

验收：无 Wiki 可以生成；已有 Wiki 检测变化不会发起模型请求；改动未提交源码可被检查；生成失败保留可用旧内容和可定位错误。

### FR-07 手写及 AI 新增页面

- 手写创建标题、分类、可选分组、slug 和 Markdown；可选关联源码。
- AI 新增允许描述主题、目标位置和关联源码，可提出一页或多页草稿。
- 新页面在应用前进入草稿，不因 Agent 创建目录条目就暴露成已完成页面。
- 校验页面 ID、slug、路径冲突与正文；多页新增作为一组变更应用。

验收：拒绝 AI 草稿时原 Wiki 无变化；重复 slug/路径被拦截；应用多页新增后目录、文件和搜索一致；无模型时仍能手写新增。

### FR-08 Markdown 正文编辑

- 提供 Markdown 编辑、预览和差异查看；不要求富文本所见即所得编辑器。
- 手动编辑使用草稿，保存草稿与应用正文明确区分。
- 切换页面、关闭编辑或退出时提示处理未保存输入；已保存草稿重启后可恢复。
- 应用前校验内容修订；外部修改发生后不得静默覆盖。

验收：正文修改外部工具可见；放弃草稿原文不变；应用前外部改文触发冲突；草稿不进入搜索结果。

### FR-09 小节与整页 AI 重写

- 小节通过明确标题位置选中；相同标题按文档位置区分，代码围栏中的 `#` 不视为标题。
- 范围为所选标题及下级内容，截止下一同级/更高级标题或文件末尾。
- AI 可读取整页和关联源码，但只能提交目标范围修改；范围外变化校验失败，不能仅依靠提示词保证。
- 整页重写为独立入口，应用前展示完整差异；空指令、页面未生成、模型不可用均明确提示。
- 任一 Provider 的 AI 维护使用 Hub 模型，不要求与生成该 Wiki 的模型一致。

验收：重复标题、嵌套标题、代码围栏和文件末节均有边界用例；小节应用后范围外内容不变；Agent 越界修改被拒绝或要求重新选择范围。

### FR-10 目录与元数据维护

- 支持修改页面标题、slug、分类、分组，以及同级页面顺序；新增分类可随创建/移动页面完成。
- 首版以单页面移动/排序为必需，不要求一次拖动整个分类树。
- 改名/移动不改变稳定页面 ID，同步更新原生目录和必要文件路径。
- 检查同名路径、保留名称、空标题及非法路径；提供清空可选分组的明确方式。
- 更新可识别的 Wiki 内部链接；无法自动处理的引用列出影响，不能默默生成断链。
- 对外部 Provider 无法原生表达的排序等元数据，需技术验证后明确呈现方式，不得虚称外部工具一定可见。

验收：移动后文件、目录、历史和可识别内部链接一致；更改标题不更换身份；排序重启后保持；冲突路径阻止应用。

### FR-11 删除与恢复

- 确认删除时显示页面及受影响引用；同时移除目录条目和当前 Markdown，并记录恢复内容。
- 删除语义是可恢复的原文删除，不是仅在 Hub 中隐藏。
- 再次生成出现已删除页面时，不直接复活；保留删除意图，交由用户决定。

验收：外部目录也反映删除；历史可恢复文件与目录；删除后搜索不再命中；重新生成不会静默恢复已删除页面。

### FR-12 关联源码维护

- 展示、添加和移除关联文件/目录；标明出处来自 Provider、用户或 AI 推断。
- 允许通过描述让 AI 提出关联源码建议，审阅后应用；未确认的推断不能当成可靠来源。
- 修改关联源码不等同于修改正文；提供独立的“依据源码更新正文”操作，生成草稿再审阅。
- 本地路径以项目为基准，拒绝越界；源文件已删除时显示失效状态，不自动丢弃历史引用。

验收：修改关联信息无需自动调用正文生成；AI 更新能使用新的范围；原生 associatedFiles 向统一引用映射且可兼容写回。

### FR-13 ChangeSet 与原生写回

- 正文、目录、删除和 AI 修改都形成针对确定修订的变更集。AI 修改必须预览后应用；简单手动操作的确认界面可合并步骤，但仍记录历史。
- 变更集记录项目/Wiki ID、目标页面 ID、来源、基准修订、前后内容/元数据、校验结果和状态。
- 建议状态：draft → applied/rejected；版本过期进入 conflicted；应用失败保持可恢复状态，不伪报 applied。
- 应用前重新核对基准及外部文件变化；同一 Wiki 的写入串行化。
- 多文件操作对用户呈现一致结果；需暂存、日志及恢复机制，不能把普通逐文件写入称为事务。
- AI 工具只操作草稿/暂存输出；未审阅前不可通过通用文件写入工具绕过应用入口修改正式 Wiki。

验收：预览、拒绝、生成失败均不改正式正文；模拟写入中断后可恢复一致目录和正文；重复应用不会重复新增；旧修订草稿不会覆盖新内容。

### FR-14 更新后保留维护修改

- 维护三方比较输入：B（旧生成基线）、L（当前维护版本）、N（新生成结果）。比较包含正文、页面增删、标题、分类、顺序和关联源码。
- L=B 时采用 N；N=B 时保留 L；两侧结果相同直接接受；两侧不同但可确定不冲突时合并；其余进入逐页审阅。
- Hub 发起更新前保存完整可恢复快照及删除意图；生成结果在完成验证与合并前不得成为用户唯一可用版本。
- 外部 CLI 不支持指定输出目录时，需在兼容的隔离工作目录或受控备份/恢复流程中生成。此方式必须通过实际 Zread 验证，不能假定它支持某个参数。
- 冲突页面保留 L，允许阅读；其他页面可维护。该 Wiki 再次生成/更新前必须解决已有冲突。
- 冲突审阅显示 B/L/N 与差异，支持保留当前、采用新生成、手动合并，以及明确处理删除/新增/移动冲突。
- 页面匹配不确定、上游重命名、新增页面 slug 撞车均进入人工处理，不根据相似标题自动覆盖。
- 完成后保存 N 作为新的生成基线，合并结果作为当前版本。不得把“已合入维护修改的结果”误记为纯生成基线。
- 首次接入没有真实旧基线时标记历史未知；可从接入点建立比较起点，保守保护无法判断的既有内容，不声称能还原接入前维护意图。

验收场景：用户改正文而上游未改时保留；两侧改同段进入冲突；两侧独立改动正确合并；用户新增页保留；删除页重现需确认；版本目录变化不丢修改；某页冲突不阻塞其他页面阅读与维护。

### FR-15 外部修改与并发边界

- 打开项目、刷新状态、应用变更前检查外部改动；仅 UI 按钮互斥不构成写入保护。
- Hub 外运行 Zread/OpenZread 可能绕过任务锁并覆盖文件。检测后提示核对，可用已有快照恢复；不承诺拦截外部覆盖。
- 最后一次 Hub 观察之后、尚未保存快照的外部编辑若被外部工具覆盖，不能保证恢复；界面应说明恢复覆盖范围。
- 外部已改动时，旧草稿转冲突；应用中的意外改动须停止并恢复/标记待恢复，而非强行写完。

验收：预览后外部修改、CLI 切换版本指针、两个 Hub 实例同时应用均有测试；外部未受管控行为不会被显示成已安全合并。

### FR-16 历史、撤销与清理

- 记录应用编辑、删除、移动、AI 修改和生成更新的时间、操作范围、状态及差异。
- 单页可恢复到指定历史版本；多页操作可整次撤销。存在后续修改时先比较，解决冲突后再恢复。
- 恢复形成新记录，不删除原历史。
- 默认保留历史，展示磁盘占用，支持手动选择清理；当前基线、冲突所需版本、运行中恢复资料不可清理。
- 磁盘空间不足时在可检测阶段阻止新写入并提示释放空间，不牺牲唯一恢复副本。

验收：删除恢复、移动撤销、后续有新修改的撤销、重启后恢复均保持一致；清理不会破坏未解决冲突。

### FR-17 跨项目全文搜索

- 搜索项目名、标题、已保存 Markdown 正文；按项目和 Provider 筛选，支持中文和英文。
- 命中显示项目、Provider/Wiki、页面、命中片段；点击跳转对应页面。
- 索引使用当前已应用内容，排除未应用草稿、旧快照和已删除页面；更新/编辑/恢复后刷新。
- 单个文件失效不阻塞全局搜索；显示索引构建/过期状态并可重建。

验收：两个项目中同名页不混淆；正文修改后命中新内容，删除后不命中；中文短语有样例验证；结果片段来自命中处，而非一律截取正文开头。

### FR-18 单 Wiki 问答

- 问答限定当前项目及当前 Wiki，可附加选中文本，引用可追溯到相应页面。
- 按 projectId + variantId 保存会话，切换后不混入其他 Wiki 的上下文。
- 默认只读；“用于修改文档”创建编辑草稿并进入同一审阅流程。
- 内容不足时说明依据不足；引用不能通过编造页面补齐。历史引用的目标变化后标明可能过期。

验收：两份 Wiki 的会话隔离；可点击有效引用；问答不产生正文写入；转为编辑后未应用前原文不变。

### FR-19 任务与退出

- 默认全局一个生成/AI 维护执行任务，其余排队；同一 Wiki 的写入任务串行。可编辑草稿，应用仍需修订检查。
- AI 问答和维护共用额度时，建议首版统一纳入 AI 队列，避免隐含并发；具体队列体验属于本稿待审查细则。
- 显示阶段、耗时、页数、警告和错误；不可计算进度时显示阶段而非虚假百分比。
- 排队任务可取消；运行任务可请求取消，等待进程终止和必要恢复。恢复完成前不允许同一 Wiki 再写入。
- 有任务关闭窗口时询问“最小化继续”或“取消并退出”；最小化后提供恢复入口。
- 意外退出后任务显示中断，先做一致性恢复，再允许用户重试；不自动再次调用模型。

验收：连续提交任务按顺序执行；取消后不会继续写文件；最小化仍运行；强制结束后重新打开不把中断显示为成功，不擅自消耗额度。

### FR-20 错误、隐私与资源访问

- 将配置缺失、鉴权失败、网络异常、格式不兼容、权限不足、磁盘不足、冲突和任务中断区分展示，提供相应恢复动作。
- 只访问用户注册项目、选择的资源范围和必要的应用数据；路径检查覆盖 `..`、绝对路径、符号链接/Windows junction、大小写和版本指针逃逸。
- 文档为非可信内容，不能将其中指令作为应用权限；日志不得记录密钥，源码和正文默认不写入诊断日志。
- Local-first 表示存储在本地，不表示 AI 离线运行；设置和操作说明应告知调用配置的模型服务时会发送必要源码/正文。

验收：越界路径无法读取/写入；不同项目不串数据；日志检查无密钥；断网仍可阅读、手写编辑和搜索已有索引。

## 6. 状态模型与一致性要求

建议分开记录以下状态，UI 组合呈现：

| 维度 | 状态 |
|---|---|
| 项目可达性 | available / missing / inaccessible |
| Wiki 内容 | missing / readable / partial / invalid |
| 源码新鲜度 | current / outdated / possibly_outdated / unknown |
| 任务 | queued / running / cancelling / succeeded / failed / cancelled / interrupted |
| 维护 | clean / draft / conflicted / recovery_required |

任务失败不等于旧 Wiki 不可读；页面冲突不等于整个项目不可用。检测与展示必须携带时间和依据，避免陈旧状态被当作实时事实。

写入成功的判定同时包含正文、原生目录、维护记录的一致性；搜索刷新可异步，但必须标记滞后。失败时不得提前推进“成功生成基线”或把部分生成结果当成完整同步完成。

### 7.1 F:\ZReadHub 的参考价值

本地同时存在旧 `hub/` 原型和模块化 `apps/api + apps/web`，应分别评估：

- `apps/api/src/scanner/wikiResolver.ts`：已处理 OpenZread 目录与 Zread `current` 文本指针，适合作为格式兼容样例。
- `scanner/fileResolver.ts`：体现 OpenZread 分类路径与 Zread 平铺文件路径的差异。
- `scanner/metadataExtractor.ts`：目前按路径加来源类型生成项目 ID，导致同项目双 Provider 分成两个项目；本次应改为一个 Project 下两个 Variant。
- `search/indexBuilder.ts`、`search/searchService.ts`：提供跨项目正文索引参考；需增加 Variant 身份、中文验证、命中片段和局部失败容错。
- `apps/web/src/components/reader`、`dashboard`、`search`：提供导航、卡片、搜索交互参考，避免新建第二套互不兼容的 Markdown 渲染体系。
- `apps/api/tests` 与 `apps/web/tests/e2e`：双格式 fixture、Reader 和搜索用例可作为新系统的验收素材。
- `hub/admin-server.mjs`：Plain Markdown 导入和源文件读取可作为后续参考；旧 Python 静态服务 + Admin API 双服务架构不作为桌面交付架构。
- `utils/pathSafety.ts` 仅做解析路径前缀判断，不能直接视为已解决 junction/符号链接逃逸；当前 Wiki 路由的路径解析也需重新审查。

参考项目证明已有阅读和搜索实现素材，不证明 Zread CLI 已支持可控生成、原生写回兼容和自动三方合并。不得直接把参考项目目录整体复制视为完成集成。

## 9. 发布验收与质量目标

### 9.1 必须通过的端到端场景

1. 干净 Windows 环境安装 → 添加非 Git 项目 → 手写 Wiki → 阅读与搜索。
2. 同项目双 Wiki → 切换阅读 → 分别编辑 → 外部读取确认写回正确目录。
3. 配置两套生成能力 → 两 Provider 各完成一次生成/更新 → 状态与实际文件一致。
4. 手写新增 + AI 新增 + 小节重写 + 移动 + 删除 → 逐项审阅应用 → 历史恢复。
5. 更新导致无冲突、同段冲突、删除重现、页面改名 → 按规则保留或解决。
6. Zread 更新 `current` 指针 → 不写旧目录；旧草稿不能覆盖新版本。
7. 写入过程中中断 → 重启 → 一致性恢复；不丢失唯一可恢复版本。
8. 多项目任务排队、取消、最小化继续、意外退出后手动重试。
9. 两项目同名页面搜索与两 Wiki 会话隔离；问答转草稿不直接修改正文。
10. 项目重新定位、移除、历史清理；源码不被误删。

### 9.2 建议的性能验收基准（待审查）

- 固定 Windows 参考机：4 核 CPU、16 GB 内存、SSD；记录机器与构建版本。
- 数据集：20 个项目、40 份 Wiki、共 2,000 页 Markdown；包含中文、长页面、图表及失效文件。
- 热索引全文搜索 p95 ≤ 1 秒；缓存页面切换 p95 ≤ 1 秒。首次扫描/建索引显示进度且不阻塞操作。
- 手动添加一个已有 Wiki 的常规项目 ≤ 30 秒；首页到任意已注册 Wiki ≤ 3 次点击，Provider 切换一次点击。
- 模型耗时和第三方 CLI 耗时不做固定响应时间承诺；任务必须持续可见、可取消或明确处于恢复阶段。
- 对损坏、只读、大文件、Unicode 路径分别设 fixture；保真往返和恢复测试为发布阻断项。
